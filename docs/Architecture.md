# 架构

SSHTree 是 macOS 27 原生应用。SwiftUI 管理窗口和资料编辑，SwiftTerm 1.20.0 渲染终端，系统 OpenSSH 处理协议与认证。应用、核心库与认证辅助程序分为三个原生 Xcode target；依赖由 Swift Package Manager 锁定。

## 数据与启动

`VaultDocument` 保存连接、凭据与删除标记。密码保持原始字符；私钥保存原始字节。云访问密钥和本机解锁密钥属于 Keychain，不写入连接资料的明文配置。

启动状态为未配置、等待解锁、加载中、可用和需要修复。`VaultRepository.restore()` 仅在没有存储配置时返回 nil。读取失败、密钥缺失和密码错误都抛出错误，UI 无权用空资料库替代损坏文件。

配置文件保存存储类型、位置和 UUID。Local 文件位于所选目录的 `v1/<vault UUID>/vault.local`；打开时列举和校验已有库，也允许输入 ID。云端缓存身份由存储类型、地域、Bucket、规范化前缀和库 UUID 确定，加密缓存位于应用数据目录的 `vaults/<stable identity>/state.vault`。重新配置同一个云库会重新关联已有缓存与待上传队列。配置切换不会删除原源文件与上传队列。

## 加密与本地保存

Local 使用随机 256 位钥匙串密钥。云端快照使用独立主密码，通过 PBKDF2-HMAC-SHA256（600000 次）及固定的资料库随机 salt 派生密钥。备份使用单独密码和独立 salt。AES-256-GCM 信封具有版本号、受认证的头部及文件大小限制。

钥匙串 service 为 `app.sshtree.mac`，不通过 iCloud 同步。macOS login Keychain 支持本机 ad-hoc 和 Developer ID 构建，系统 ACL 决定实际访问。更换未使用稳定签名的应用程序时，系统可能再次请求钥匙串授权。

敏感目录权限为 `0700`，文件为 `0600`。保存先验证原文件，再写入前一份有效密文与原子替换的新文件。备份导入进行合并；解锁失败时也可以完整验证备份并恢复到新的 Local 目录，成功后才切换配置。

## 云端提交图

对象布局：

```text
<prefix>/v1/<vault UUID>/
  vault.json
  blobs/<SHA256 of ciphertext>.vault
  commits/<SHA256 of ciphertext>.commit
```

描述文件固定包含版本、库 UUID、随机 salt 和初始提交 ID。创建先上传初始加密快照及提交，最后发布描述文件。打开库必须取得描述文件并验证初始提交，不能根据空列表推断“新库”。

每次编辑先落入本地加密状态和待上传队列，再上传快照，最后发布小型加密提交。提交保存真实父修订。重试复用对象键和相同字节；不会以新的加密 nonce 冒充同一次重试。没有可被多设备覆盖的 latest 指针。

待上传密文保存在独立、按内容寻址的文件中，队列清单属于加密状态。快照缓存仅保留当前 heads 与合并基线；旧快照可从不可变 blob 重新读取，避免每次编辑都把整个历史资料重复写入状态文件。

OSS 使用官方 V4 签名，COS 使用官方请求签名；HTTP 仅使用 HTTPS，并拒绝重定向以避免泄露 Authorization。禁止覆盖上传前检查 Bucket 版本控制状态：启用或暂停时拒绝写入，防止服务商忽略禁止覆盖头。

同步分页扫描全部提交，与本地已知提交取并集，并直接读取缺失父提交。COS 列举延迟不会删除已知修订。多设备分叉通过共同基线合并独立修改；相同连接、凭据或删除的分歧保留所有选项，等待用户选择。多个共同基线有不同值时不能任意选择其中一个当作唯一基线。

`VaultRepository` actor 统一管理保存与同步。网络 await 前后检查源标识和编辑 generation；下载不能覆盖新编辑。UI 用 `VaultDocumentReconciler` 保留等待仓库操作期间产生的编辑，仓库负责唯一的提交历史。

迁移先验证目标并合并资料。存在冲突时保留原源为活动源，展示暂存目标的冲突；全部选择完成且源版本未变化后，才激活目标。目标自身已有未解决冲突时先拒绝迁移，避免丢失已有选项。普通打开则直接切换已验证的目标，不隐式复制源资料。

## SSH 会话

每个 `TerminalSession` 拥有独立 PTY、终端缓冲、OpenSSH 进程、控制 socket 和认证 socket。SwiftTerm 仅负责绘制、输入与尺寸变化；`SSHPTYProcess` 负责进程组信号、FD 关闭及唯一一次 waitpid 回收。fork 后重置信号状态，避免继承 Swift 并发线程的信号屏蔽。

OpenSSH 使用 `StrictHostKeyChecking=ask`。首次连接的实际指纹通过认证 helper 原样送到界面，变更的已知密钥直接拒绝。连接状态仅在控制主进程成功回应真实 mux 检查后更新。服务器过早退出、认证失败或远端终端失败会保留输出并显示错误。

`SSHTreeAskPass` 位于应用的 `Contents/MacOS`。通过权限受限的 Unix socket 请求响应，验证 peer UID、SSH 进程祖先与 helper 可执行路径。环境和启动参数只包含 socket 位置与进程标识。未知认证提示需要一次性人工输入，不自动返回已保存密码。

导入私钥只在认证期间写入会话临时目录；认证成功、失败、取消、关闭及退出时清理。启动扫描只清理本应用创建且所有者进程已结束的临时目录，不扫描或修改系统 SSH 配置。

主窗口保留所有终端视图，只有当前标签页接收焦点。设置是独立窗口。关闭活跃标签页、主窗口或退出需要确认，未保存资料必须先成功落盘。

## 界面与资源

原生分栏、侧边栏、工具栏和玻璃控件遵循系统颜色、字体及辅助功能。终端正文使用实色背景，字体和深浅外观可在设置调整。

`Resources/AppIcon.icon` 是 Icon Composer 原生文件，采用深色玻璃终端、流光 S 和青绿光标，显示 `> S_`。Default、Dark 使用选定彩色图案；Mono 使用独立 SVG 轮廓，通过原生外观特化切换图层。彩色层关闭额外玻璃处理，保持选定图案的材质与形状。`IconPreview.png` 由 Icon Composer 原生工具以 macOS 27 Design Generation 导出，仅用于文档展示。Xcode 编译原生图标与兼容 icns；认证 helper、核心框架、SwiftTerm 资源与许可证随 `.app` 一起分发。
